# v0.2.0 - Reproducible Registration and Real-Rosbag Evaluation

v0.2.0 moves CudaRobotics from individual demos and benchmark scripts toward
quality-gated, reusable evaluation workflows.

## Highlights

- Unified rigid-registration suite covering five CudaRobotics GPU algorithms
  and optional probreg/Open3D CPU baselines.
- Deterministic rotation, translation, RMSE, runtime, and quality-gate outputs
  in CSV and Markdown.
- CPU-reference versus GPU registration consistency tests.
- `RegistrationResult` typed Python API while preserving tuple-returning
  `register()` compatibility.
- Real-rosbag CUDA MPPI report combining recorded motion, LaserScan clearance,
  controller diagnostics, evidence mode, and explicit pass/fail checks.
- Configurable command, odometry, and scan topics for offline rosbag analysis.
- Synchronized Python and ROS package version gate.
- Local CPU/GPU release preflight with per-gate logs, a machine-readable
  manifest, and explicit remote-CI boundaries.
- Python sdist/wheel content verification with native-extension, bundled-core,
  metadata, and SHA256 checks.
- Commit-bound Build, Python manylinux, and ROS 2 CI attestations plus a single
  aggregate release validator that rejects mixed commits or moved refs.

## Registration

```bash
python3 scripts/run_registration_suite.py \
  --scenarios lumpy_partial low_overlap outlier_partial large_offset \
  --sizes 2000 8000 --trials 3
```

Use `registrar.register_result(...)` for normalized `rotation`, `translation`,
and `info` fields. Existing `rotation, translation, info =
registrar.register(...)` code remains supported.

## Real-Rosbag MPPI Evaluation

```bash
python3 scripts/evaluate_mppi_rosbag.py /data/run/run_0.db3 \
  --diagnostics-csv /data/run/diagnostics.csv \
  --output-dir build/mppi_rosbag_evaluation/run_0
```

Recorded bags cannot prove closed-loop success because their motion does not
react to newly computed commands. Reports label this explicitly as recorded
motion or shadow-controller evidence.

## Compatibility

- Python package and ROS package version: `0.2.0`
- Python source compatibility: 3.9-3.12
- Published manylinux wheels: CPython 3.10 and 3.12 on Linux x86_64
- CUDA Toolkit: 12.x
- Existing Python registration tuple API remains supported.
- Wheels remain Linux x86_64 and require a compatible NVIDIA driver.
