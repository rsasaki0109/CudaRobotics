# v1.0.0 - End-to-End GPU Autonomy

v1.0.0 promotes CudaRobotics from a collection of CUDA robotics demos to a
versioned autonomy stack connecting GPU LiDAR odometry, voxel mapping, ESDF,
and Nav2 CUDA MPPI control.

These notes describe the release-candidate source. They do not authorize a
`v1.0.0` tag or GitHub Release. Publication remains fail-closed until the
immutable-tag evidence in
[`v1.0.0_release_checklist.md`](v1.0.0_release_checklist.md) passes.

## Highlights

- ROS 2 Jazzy CudaNav bringup connecting GPU KISS-ICP, rolling voxel mapping,
  typed ESDF, a Nav2 voxel-costmap layer, and CUDA MPPI.
- DiffDrive, Ackermann, and Omni controller configurations.
- Reusable Python GPU MPPI and rigid/non-rigid registration APIs, including
  CUDA DLPack costmap ingestion.
- Source distribution and CPython 3.10/3.12 manylinux x86_64 wheel workflows.
- Content-bound evidence contracts for clean source, datasets, GPU identity,
  commands, outputs, reports, and release archives.
- Reproducible systems-paper and contact-rich Diff-MPPI artifact ledgers that
  keep unsupported claims and negative results visible.

## Verified CudaNav Results

The retained ROS 2 Jazzy closed-loop simulation ran 30/30 alternating
command-driven traversals over 1,325.535 seconds on an NVIDIA GeForce GTX
1660 Ti:

- zero collisions;
- 0.153 m final goal distance;
- 0.00283% odometry drift;
- 32/13,268 controller deadline misses (0.241%);
- zero diagnostic warnings, errors, or failure-counter increments.

The retained Autoware Istanbul real-sensor shadow run produced 793 controller
diagnostic samples over 79.025 seconds:

- 790/790 pointcloud-command pairs;
- 3.166 ms mean and 4.801 ms p95 solve latency;
- 0.9907 mean valid-rollout ratio;
- 3.535 m minimum front clearance;
- 804 odometry, 796 occupancy, and 794 ESDF outputs.

The Istanbul result is recorded/shadow evidence. Its commands do not alter the
recorded vehicle motion and it is not presented as real-world closed-loop
navigation.

## Supported Surfaces

- Python source: Linux x86_64, Python 3.9-3.12, CUDA Toolkit 12.x.
- Published Python wheels: CPython 3.10 and 3.12, manylinux x86_64, with a
  compatible NVIDIA driver at runtime.
- ROS 2: Jazzy on Ubuntu 24.04 with CUDA Toolkit 12.6.
- Docker source demo: NVIDIA driver 525 or newer plus NVIDIA Container
  Toolkit.
- Colab: experimental Python MPPI and registration quickstart.

The authoritative versions, commands, and release-readiness gates are in
[`../v1_support_matrix.json`](../v1_support_matrix.json).

## Compatibility

- Python and supported ROS 2 package version: `1.0.0`.
- The v0.2 tuple-returning registration API remains supported alongside
  `register_result(...)`.
- Wheels remain Linux x86_64 only.
- Jetson is experimental until a retained device-specific result is
  published.
- Benchmark and reproduction-zoo variants are research implementations; an
  individual reproduction document defines whether a variant is supported,
  partial, or a negative result.

## Release Boundaries

The release is not ready solely because source packages carry version
`1.0.0`. The final tag must still prove, on one immutable commit:

- a fresh-clone, no-cache CudaNav quickstart within 15 minutes;
- strict ROS 2 closed-loop, real-rosbag shadow, and multi-model GPU evidence;
- a smoke test of the published GHCR image by immutable digest;
- a deployed documentation site re-fetched from its public URLs;
- one content-bound evidence bundle and canonical archive covering all four
  attestations.

Missing Docker, GPU, ROS 2, second-model, or public-HTTP evidence is a failed
release gate, not a skipped pass.
