# v0.3.0 Release Checklist

This is the authoritative publication checklist for CudaRobotics v0.3.0.
Tags are immutable: if a published artifact is wrong, publish a patch release
instead of moving `v0.3.0`.

## Release target

- Tag: `v0.3.0`
- Base branch: `master`
- Python and ROS package version: `0.3.0`
- Release notes: [`v0.3.0_notes.md`](v0.3.0_notes.md)

## Pretag gates

Run on the exact clean `master` commit:

```bash
python3 scripts/test_version_consistency.py
python3 scripts/validate_v1_support_matrix.py
python3 scripts/test_python_core_sync.py
python3 -m pytest python/tests -q
git diff --check
```

Dispatch and require successful exact-commit runs of:

- `.github/workflows/build.yml`
- `.github/workflows/python-package.yml`
- `.github/workflows/ros2_cuda_mppi.yml`
- `.github/workflows/cudanav-systems-paper.yml`

Download the commit-bound CI evidence from all four workflows. Validate the
Build and Python attestations with `scripts/validate_release_ci.py`, the ROS
attestation with `scripts/validate_cudanav_ros_ci.py`, and the systems-paper
archive with its independent validator and SHA-256 sidecar.

Download `cudarobotics-wheels` and `cudarobotics-manylinux-wheels` from the
successful Python workflow into one clean directory:

```bash
python3 scripts/verify_python_release_artifacts.py \
  --dist-dir build/release_v0.3.0/publish \
  --json build/release_v0.3.0/publish/python_artifacts.json \
  --require-clean
```

The verified directory must contain:

- `cudarobotics-0.3.0.tar.gz`
- one CPython 3.10 manylinux x86_64 wheel
- one CPython 3.12 manylinux x86_64 wheel

## Publication

After every gate is bound to the same clean `master` commit:

```bash
git tag -a v0.3.0 -m "v0.3.0 - Integrated CudaNav Release"
git push origin v0.3.0
```

Create the GitHub release from `v0.3.0_notes.md`. Attach the verified source
distribution, both portable manylinux wheels, the exact-commit systems-paper
evidence archive, and its SHA-256 sidecar. The tag push also triggers the GHCR
Docker image workflow.

## Post-publication verification

Re-download every GitHub release asset into an empty directory. Compare its
SHA-256 and byte size with the pre-upload file, reopen the Python archives with
`scripts/verify_python_release_artifacts.py`, and independently validate the
evidence archive and checksum. Confirm that:

- the release tag resolves to the gated `master` commit;
- the release is not a draft or prerelease;
- the Colab and documentation links resolve through `v0.3.0`;
- the tag-triggered Docker workflow status is recorded without overstating
  local or self-hosted GPU validation.
