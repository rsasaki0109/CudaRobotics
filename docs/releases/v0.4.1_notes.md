# v0.4.1 - CudaNav Docker Image Fix

CudaRobotics v0.4.1 is a patch release of v0.4.0. It publishes the CudaNav
Docker image that the v0.4.0 tag could not produce and ships the same Python
and ROS 2 functionality under version 0.4.1. This is a pre-1.0 release; the
separate v1.0 support contract is not declared ready by this release.

## Fixes

- **Docker image build.** The v0.4.0 tag-triggered image failed because
  `src/gpu_kiss_icp.cu` includes private KISS-ICP headers
  (`kiss_icp_spatial.cuh` and related headers) that `docker/Dockerfile` did not
  copy. The image now copies the whole `include/` tree.
- **Build-context gate.** `scripts/check_docker_build_context.py` resolves the
  CMake repository-root references and transitive quoted includes of every
  package the image builds against the Dockerfile's copied paths, without
  Docker or CUDA. It runs in repository checks and before the image build, and
  rejects the v0.4.0 Dockerfile.
- **Windows checkouts.** `.gitattributes` keeps shell scripts LF so images
  built from a Windows checkout do not fail with `bash\r: No such file`.

No CUDA kernel, Python API, ROS 2 interface, or browser demo behavior changes
relative to v0.4.0.

## Install

The Python distribution targets Linux x86_64 and CPython 3.10 or 3.12:

```bash
python -m pip install ./cudarobotics-0.4.1-*.whl
```

The Docker image runs the Nav2 controller benchmark by default and the short
CudaNav closed loop with `cudanav`:

```bash
docker run --rm --gpus all ghcr.io/rsasaki0109/cuda-mppi-controller-demo:v0.4.1
docker run --rm --gpus all -v "$PWD/out:/out" \
  ghcr.io/rsasaki0109/cuda-mppi-controller-demo:v0.4.1 cudanav
```

ROS 2 packages target Jazzy / Ubuntu 24.04 with CUDA 12.6. The Colab notebook
in this source release is pinned to the immutable `v0.4.1` tag.

## Verification and limitations

Distribution files are attached only after their exact-tag workflows pass and
the archives are independently re-verified; the image is claimed only after
the tag-triggered Docker workflow succeeds. A local physical-GPU run of the
fixed image passed the `wall_gap` controller benchmark before tagging; it is a
smoke check, not new release evidence. Existing partial or negative native and
real-dataset evidence is unchanged.
