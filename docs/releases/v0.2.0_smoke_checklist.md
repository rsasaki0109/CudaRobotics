# v0.2.0 Release Smoke Checklist

This checklist is the authoritative pre-tag gate for v0.2.0. Publishing and
tag creation remain separate, explicit release actions.

## Release Target

- Tag: `v0.2.0`
- Base branch: `master`
- Release notes: [`v0.2.0_notes.md`](v0.2.0_notes.md)
- Python and ROS package version: `0.2.0`

## Required Checks

Run the local gates and retain their logs and manifest:

```bash
python3 scripts/run_release_preflight.py \
  --profile gpu \
  --build-dir build \
  --dist-dir build/release_v0.2.0/dist \
  --output-dir build/release_v0.2.0/preflight \
  --require-clean
python3 scripts/validate_release_preflight.py \
  build/release_v0.2.0/preflight \
  --profile gpu --commit "$(git rev-parse HEAD)"
```

The independent validator checks the clean commit, profile, complete check
matrix, and SHA-256/size binding of every gate log, Python artifact manifest,
and registration CSV/Markdown. The preflight report does not infer remote CI
success. GitHub Build, Python manylinux wheels, and ROS 2 remain explicit
external gates on the final release-candidate commit.

Acquire those remote gates without relabelling a pull-request run:

```bash
RC_COMMIT="$(git rev-parse HEAD)"
RC_REF="$(git branch --show-current)"
gh workflow run build.yml --ref "$RC_REF"
gh workflow run python-package.yml --ref "$RC_REF"
gh workflow run ros2_cuda_mppi.yml --ref "$RC_REF"
```

Build and Python package manual runs upload
`github-build-ci-evidence-$RC_COMMIT` and
`python-package-ci-evidence-$RC_COMMIT`. Validate the downloaded JSON files:

```bash
python3 scripts/validate_release_ci.py github_build_ci_evidence.json \
  --gate github_build --commit "$RC_COMMIT"
python3 scripts/validate_release_ci.py python_package_ci_evidence.json \
  --gate python_manylinux_wheels --commit "$RC_COMMIT"
python3 scripts/validate_cudanav_ros_ci.py ros_jazzy_ci_evidence.json \
  --commit "$RC_COMMIT"
```

The CI evidence contract accepts only `push` or `workflow_dispatch`, records
the workflow run URL/attempt/ref, and binds the expected checks and artifact
names. The Python attestation is emitted only after both Python-version test
jobs and the CPython 3.10/3.12 manylinux job pass. Its final job downloads both
artifact groups, independently reopens and hashes them, and binds the resulting
`python_artifacts.json` hash into the CI attestation. A dispatch ref selects
the remote branch or tag; the subsequent `--commit "$RC_COMMIT"` validation is
what prevents a moved branch from being accepted.

After downloading both CI attestations, the ROS attestation, and both Python
artifact groups, make the one final decision:

```bash
python3 scripts/verify_python_release_artifacts.py \
  --dist-dir build/release_v0.2.0/publish \
  --json build/release_v0.2.0/publish/python_artifacts.json \
  --require-clean
python3 scripts/validate_v0_2_release.py \
  --commit "$RC_COMMIT" \
  --cpu-preflight build/release_v0.2.0/preflight_cpu \
  --gpu-preflight build/release_v0.2.0/preflight_gpu \
  --build-ci build/release_v0.2.0/evidence/github_build_ci_evidence.json \
  --python-ci build/release_v0.2.0/evidence/python_package_ci_evidence.json \
  --ros-ci build/release_v0.2.0/evidence/ros_jazzy_ci_evidence.json \
  --dist-dir build/release_v0.2.0/publish \
  --python-artifacts build/release_v0.2.0/publish/python_artifacts.json \
  --output build/release_v0.2.0/release_gate.json
```

This aggregate gate independently reruns every child validator, requires one
remote ref and three distinct workflow runs, reopens the sdist and both
manylinux wheels, rehashes every distribution file, verifies the CI-to-artifact
manifest binding, and retains the public real-rosbag failure as an explicit
negative result. Only `status: ready` authorizes the tag procedure below.

## Required Artifacts

- `cudarobotics-0.2.0.tar.gz`
- CPython manylinux x86_64 wheels produced by the package workflow
- Registration suite CSV and Markdown from the release candidate commit
- At least one real-rosbag evaluation JSON and Markdown report
- GitHub release notes from `v0.2.0_notes.md`

Do not mark the release ready when a GPU check was merely skipped. Record the
GPU model, driver, CUDA version, command, and output location for both the
registration and rosbag evaluations.

## Publish Contract

Publishing is allowed only from a clean `master` checkout at the exact commit
that produced all required CI and GPU evidence. Never move or replace a
published release tag; use a patch release if a published artifact is wrong.

Download both artifact groups from the successful final-RC Python package run,
put the sdist and wheels in one staging directory, and verify them:

```bash
git fetch origin --tags
git switch master
git pull --ff-only origin master
test -z "$(git status --porcelain)"
test "$(git rev-parse HEAD)" = "$(git rev-parse origin/master)"

RUN_ID=<successful-final-rc-python-package-run>
rm -rf build/release_v0.2.0/publish
mkdir -p build/release_v0.2.0/publish
gh run download "$RUN_ID" \
  --name cudarobotics-wheels \
  --dir build/release_v0.2.0/publish
gh run download "$RUN_ID" \
  --name cudarobotics-manylinux-wheels \
  --dir build/release_v0.2.0/publish

python3 scripts/verify_python_release_artifacts.py \
  --dist-dir build/release_v0.2.0/publish \
  --json build/release_v0.2.0/publish/python_artifacts.json \
  --require-clean
```

Create an annotated tag at that verified commit. Pushing the tag triggers the
GHCR Docker workflow:

```bash
git tag -a v0.2.0 \
  -m "v0.2.0 - Reproducible Registration and Real-Rosbag Evaluation"
git push origin v0.2.0
```

Create the GitHub release with the sdist and portable manylinux wheels. The
workflow-local `linux_x86_64` wheel is evidence, not a published portable
asset:

```bash
gh release create v0.2.0 \
  --verify-tag \
  --title "v0.2.0 - Reproducible Registration and Real-Rosbag Evaluation" \
  --notes-file docs/releases/v0.2.0_notes.md \
  build/release_v0.2.0/publish/cudarobotics-0.2.0.tar.gz \
  build/release_v0.2.0/publish/*manylinux*.whl
```

Post-publish verification:

```bash
gh release view v0.2.0
gh run list --workflow docker-image.yml --limit 1
docker pull ghcr.io/rsasaki0109/cuda-mppi-controller-demo:v0.2.0
docker run --rm --gpus all \
  ghcr.io/rsasaki0109/cuda-mppi-controller-demo:v0.2.0
```
