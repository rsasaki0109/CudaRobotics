# v1.0.0 Release Checklist

This is the authoritative operator checklist for the v1.0.0 tag. The
machine-readable decision remains
[`../v1_support_matrix.json`](../v1_support_matrix.json) plus its validator.

## Release Target

- Version: `1.0.0`
- Tag: `v1.0.0`
- Base branch: `master`
- Release notes: [`v1.0.0_notes.md`](v1.0.0_notes.md)
- Evidence contract:
  [`../v1_support_matrix.md`](../v1_support_matrix.md)

## 1. Pre-Tag Source Gate

Start from a clean, synchronized checkout and retain the candidate commit:

```bash
git fetch origin --tags
git switch master
git pull --ff-only origin master
test -z "$(git status --porcelain)"
test "$(git rev-parse HEAD)" = "$(git rev-parse origin/master)"
RC_COMMIT="$(git rev-parse HEAD)"
```

Run the source contracts:

```bash
python3 scripts/test_version_consistency.py
python3 scripts/test_cudanav_contract.py
python3 scripts/validate_v1_support_matrix.py
python3 scripts/validate_paper_artifacts.py
```

Expected before tagging:

- version consistency reports source `1.0.0`;
- the support matrix is `valid: true`;
- `python_at_target` and `ros_at_target` are true;
- support-matrix `ready` is still false because post-tag attestations do not
  exist yet.

Require successful Build, Python package, and ROS 2 Jazzy workflows on
`RC_COMMIT`. Download and independently validate their commit-bound evidence.
Do not substitute pull-request checks for push or workflow-dispatch evidence.

Assemble those three exact runs into one content-bound candidate bundle:

```bash
gh workflow run v1-release-candidate.yml --ref master \
  -f build_run_id="$BUILD_RUN_ID" \
  -f python_run_id="$PYTHON_RUN_ID" \
  -f ros_run_id="$ROS_RUN_ID"
```

Download `v1-release-candidate-$RC_COMMIT` and independently validate it:

```bash
python3 scripts/v1_release_candidate.py validate \
  build/v1_release_candidate/bundle.json \
  --commit "$RC_COMMIT"
```

The bundle must report `passed: true`; it rejects a different commit, a
pull-request event, a non-master ref, reused run IDs, a stale Python source
manifest, or any post-assembly edit.

## 2. Immutable Tag

Create the tag only after the pre-tag source and CI gates pass:

```bash
test "$(git rev-parse HEAD)" = "$RC_COMMIT"
git tag -a v1.0.0 -m "v1.0.0 - End-to-End GPU Autonomy"
git push origin v1.0.0
test "$(git rev-list -n 1 v1.0.0)" = "$RC_COMMIT"
```

Never move or replace the published tag. Use a patch release if the tagged
source or an attached artifact is wrong.

## 3. Four Post-Tag Attestations

All four attestations must name `v1.0.0`, version `1.0.0`, and `RC_COMMIT`.

### Fresh-clone quickstart

On a clean Docker/NVIDIA host with no pre-existing `cudarobotics` image:

```bash
python3 scripts/run_v1_quickstart.py \
  --output-dir build/v1_quickstart \
  --ref v1.0.0 --profile release
python3 scripts/validate_v1_quickstart.py \
  build/v1_quickstart --profile release --commit "$RC_COMMIT"
python3 scripts/publish_v1_quickstart_attestation.py \
  --evidence-dir build/v1_quickstart \
  --output build/v1_inputs/quickstart.json
```

The clone, no-cache build, and CudaNav run must complete within 900 seconds.

### CudaNav systems release

Regenerate the strict CudaNav suite from the tag, including ROS 2 Jazzy
closed-loop evidence, the declared real-rosbag shadow dataset, and at least
two distinct physical GPU models. Publish
`cudanav_release_evidence` only after
`publish_cudanav_systems_evidence.py` independently validates the complete
suite. A missing second model is a blocker.

### Published Docker image

After the tag-triggered image workflow publishes GHCR:

```bash
gh workflow run v1-docker-gpu-evidence.yml \
  --ref v1.0.0 -f tag=v1.0.0
```

The self-hosted GPU job must pull the published image, bind its immutable
digest and OCI source revision to `RC_COMMIT`, run CudaNav successfully, and
upload `docker_gpu.json`.

### Deployed documentation

```bash
gh workflow run v1-docs-deploy.yml \
  --ref v1.0.0 -f tag=v1.0.0
```

The workflow must preserve the existing gallery tree, deploy the tagged docs,
re-fetch the public index/install/Nav2/manifest URLs, and upload
`documentation.json`.

## 4. Bundle and Final Decision

Assemble the unedited downloaded attestations:

```bash
python3 scripts/assemble_v1_release_bundle.py \
  --quickstart build/v1_inputs/quickstart.json \
  --cudanav build/v1_inputs/cudanav.json \
  --docker-gpu build/v1_inputs/docker_gpu.json \
  --documentation build/v1_inputs/documentation.json \
  --output-dir build/v1_release_bundle \
  --commit "$RC_COMMIT"
python3 scripts/validate_v1_support_matrix.py \
  --require-ready \
  --evidence-bundle build/v1_release_bundle/bundle.json \
  --release-commit "$RC_COMMIT"
```

Only `ready: true` authorizes the GitHub Release.

Create and validate the canonical archive:

```bash
python3 scripts/archive_v1_release_bundle.py \
  build/v1_release_bundle/bundle.json \
  --output build/cudarobotics-v1.0.0-evidence.zip \
  --commit "$RC_COMMIT"
python3 scripts/validate_v1_release_archive.py \
  build/cudarobotics-v1.0.0-evidence.zip \
  --checksum build/cudarobotics-v1.0.0-evidence.zip.sha256 \
  --commit "$RC_COMMIT"
```

## 5. Publish and Re-Download

Create the GitHub Release with the verified sdist, CPython 3.10/3.12
manylinux wheels, evidence ZIP, and checksum:

```bash
gh release create v1.0.0 \
  --verify-tag \
  --title "v1.0.0 - End-to-End GPU Autonomy" \
  --notes-file docs/releases/v1.0.0_notes.md \
  build/publish/cudarobotics-1.0.0.tar.gz \
  build/publish/*manylinux*.whl \
  build/cudarobotics-v1.0.0-evidence.zip \
  build/cudarobotics-v1.0.0-evidence.zip.sha256
```

Re-download the public evidence bytes and run
`validate_v1_release_archive.py` again against `RC_COMMIT`. Confirm the public
release assets, GHCR digest, documentation manifest, and tag all identify that
same commit.

## Stop Conditions

Do not publish when any of these is true:

- the checkout is dirty or the candidate branch moved;
- any source, CI, GPU, Docker, ROS 2, documentation, or archive validator
  fails;
- a required check was skipped because its hardware or service was
  unavailable;
- the four attestations do not share one commit;
