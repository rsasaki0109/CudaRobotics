Soft deadline, not real-time preemption: every mission plan times CPU sampling + cost evaluation + CPU softmin/update, including GPU transfers. An over-budget evaluator is allowed to finish, then its command is discarded and the mission stops before motion. Late durations remain in JSON and count as deadline stops, not safe arrivals. The main thread cannot forcibly interrupt JavaScript or GPU work. One evaluator warmup per trial excludes buffer setup. Checks, drawing, motion and between-step yields are untimed; simulated time advances only on accepted commands. Path length sums the two guarded model substep segments. Three trials do not establish reliability, continuous collision safety or a GPU-quality winner.

Same parallel idea. A browser-native backend.

Like the native CUDA controller, one GPU invocation evaluates one candidate trajectory. A softmin weights the sampled control sequences; the first command moves the robot, then the horizon shifts. Guide waypoints in the slalom scene provide a global route; MPPI is a local controller.

This is a simplified JavaScript / WGSL port, not CUDA running in a browser, not the full Nav2 controller and not a native performance benchmark. Sampling, weight reduction and drawing run on the CPU. WebGPU evaluates rollout costs; unsupported devices automatically use the JavaScript reference. No installs, external assets, telemetry, camera permissions or backend server.
