01 / DESIGN THE AISLE

Add or remove obstacles, relocate the robot and set a destination. The doorway preset makes footprint limits easy to test.

02 / COMPUTE CLEARANCE

Two GPU passes compute squared Euclidean distances, one invocation per grid cell. Obstacle cells are conservatively expanded to their full area.

03 / FIND A ROUTE

CPU A* respects robot radius + safety margin. Collision-checked shortcuts reduce unnecessary corners; blocked routes stop the mission.

04 / REPRODUCE

Export the occupancy map, footprint, route coordinates and clearance report. Import the same map to compare footprint choices.

A useful planning experiment, not a robot safety system.

The robot is a kinematic disk following a geometric route at 0.8 m/s, with a 0.05 s simulation step. This is not the native CUDA/Nav2 controller, a physics simulation, SLAM, or a guarantee of safe physical deployment. GPU acceleration covers the distance field; A*, motion checks and Canvas drawing run on the CPU. Unsupported devices use the identical CPU distance-field reference.

The fixed grid is 128 × 96 cells at 0.125 m/cell. Distance values are conservative lower bounds: distance to occupied cell centres minus a half-cell diagonal, capped by map boundaries. Cell lookup also accounts for subcell position. Narrow passages can therefore be rejected conservatively. JSON import accepts this documented grid format, not arbitrary ROS maps. Exported routes are experiment data, not executable robot commands.
