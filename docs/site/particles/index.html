32 LiDAR beams. Known map. No camera or uploads. On mobile, start with 4,096 particles if updates are slow.

01 / PREDICT + SCORE

One invocation per pose. Transform 32 scan endpoints and evaluate their distance to mapped surfaces.

02 / PREFIX SCANS

256-lane workgroups build a weight CDF. A second scan combines group totals and posterior moments.

03 / RESAMPLE

Each invocation independently searches the CDF. Good hypotheses survive; 3% global proposals keep exploration alive.

04 / DRAW

Instanced particle sprites read the GPU state directly. Only 32 bytes of summary statistics return to the CPU.

This is the parallel part.

On WebGPU, all four compute passes and particle drawing run on the GPU. The CPU only generates the synthetic LiDAR scan, moves the ground-truth robot and draws the map/scan overlay. The beam counter is an upper bound of 32 tests per particle; invalid poses skip scoring. It is not measured hardware occupancy or ray-tracing throughput. Updates advance 0.1 simulation seconds, independent of wall-clock speed.

This is a browser-native WGSL demonstration of the CUDA-style particle-per-thread pattern, not CUDA executing in a browser or a native CUDA benchmark. It is likelihood-field Monte Carlo localization on a known 2D map, not SLAM. The posterior mean can lie between competing modes before convergence. Unsupported devices get a clearly labeled 512-particle CPU preview.
