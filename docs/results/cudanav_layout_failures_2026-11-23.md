# CudaNav pedestrian layouts: failure attribution

Generated by `scripts/analyze_cudanav_layout_failures.py`, which replays the deterministic
72-run layout sweep (72 runs) with per-frame instrumentation. Synthetic data.

A frame is stalled when route progress over the next 2 s is below 0.10 m.
With a pedestrian within 0.6 m of the robot's edge its cause is `wait` if the planner still has
collision-free rollouts, `pushed_back` if every rollout collides and the pedestrian advances 0.10 m or more
against the robot's heading over the window, and `backout` if every rollout collides otherwise. Without one it is
`ghost` if non-wall occupied cells lie within 1.0 m, `false_track` if a planner obstacle
within 1.0 m is more than 0.7 m from every pedestrian, else `other`.
