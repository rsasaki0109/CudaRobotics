# MathematicalRobotics selected port

This document records the deliberately small port from
[scomup/MathematicalRobotics](https://github.com/scomup/MathematicalRobotics).
The upstream project is MIT-licensed. The port keeps the upstream attribution
in the relevant headers and is covered by the repository's existing
[`LICENSE.md`](../LICENSE.md).
The redistributed upstream notice is also kept in
[`mathr_license.md`](mathr_license.md).

## What was selected

| CudaRobotics component | Upstream source | Purpose |
|---|---|---|
| [`include/cudarobotics/lie_group_math.cuh`](../include/cudarobotics/lie_group_math.cuh) | `mathR/utilities/math_tools.py` | Dependency-free host/device SO(2), SE(2), SO(3), and SE(3) exponential/logarithm primitives |
| [`include/cudarobotics/imu_preintegration.hpp`](../include/cudarobotics/imu_preintegration.hpp) | `mathR/imu_preintegration/preintegration.py`, `imu_factor.py` | Fixed-size IMU preintegration, bias correction, state prediction, and factor linearization |
| [`include/cudarobotics/robust_loss.cuh`](../include/cudarobotics/robust_loss.cuh) | `mathR/utilities/robust_kernel.py` | Host/device L2, Huber, pseudo-Huber, and Cauchy rho coefficients |

The graph solver, EKF/PF, ICP, and SciPy/SuiteSparse-oriented optimization
layers were not copied wholesale. CudaRobotics already has native versions
of several of those tracks, and the selected math is more reusable as a
fixed-size CUDA core.

## Conventions

- Matrices are row-major fixed-size arrays; no Eigen or SciPy types cross the
  core API boundary.
- `SE(3)` tangents use `[rho_x, rho_y, rho_z, omega_x, omega_y, omega_z]`.
- An IMU `NavState` stores `R` (body to navigation frame), navigation-frame
  position `p`, and navigation-frame velocity `v`.
- IMU bias correction is evaluated around the preintegrator's stored
  linearization bias. Calibration rotation and lever-arm centripetal
  correction are handled before the integration step.
- The CUDA factor API is `linearize_imu_factor`; its output is a 9-vector
  residual with 9x9 state Jacobians and a 9x6 bias Jacobian.

## Existing SLAM integration

The current GPU 3D pose graph optimizes a 6-DoF pose state, whereas a full IMU
factor optimizes pose, velocity, and bias. Its consecutive odometry edges now
use a small pose-only bridge generated by `ImuPreintegrator`; the full
velocity/bias factor remains available for a future 15-DoF backend without
duplicating integration math in the pose graph.

## Verification

From a configured build directory:

```text
cmake --build build --target test_lie_group_math test_imu_preintegration test_robust_loss --config Debug
ctest --test-dir build -C Debug -R "test_lie_group_math|test_imu_preintegration|test_robust_loss" --output-on-failure
cmake --build build --target test_imu_preintegration_gpu --config Debug
ctest --test-dir build -C Debug -R "test_imu_preintegration_gpu" --output-on-failure
```

The GPU smoke test constructs the preintegrator and factor inside a CUDA
kernel and compares the complete result with the CPU reference.
