# GPU Dense Direct (Photometric) Visual Odometry

`src/gpu_direct_vo.cu`

Dense direct visual odometry - the front-end DSO / LSD-SLAM popularised:
recover camera motion by minimising the photometric error over **all** pixels
directly, with no feature extraction. This is the dense counterpart to the
repo's sparse Lucas-Kanade demo (`gpu_lk_optical_flow`): instead of one
independent flow per feature, the whole image votes into a single shared pose
via Gauss-Newton. Maps onto **one thread = one pixel**.

![demo](https://rsasaki0109.github.io/CudaRobotics/gpu_direct_vo.gif)

## Pipeline

A planar SE(2) warp `p = (tx, ty, theta)` between a reference image `I` and a
moved frame `J`. Each Gauss-Newton iteration:

```
r(x) = J(W(x;p)) - I(x)              photometric residual
Jrow = grad J(W(x;p)) . dW/dp        3-vector
H += Jrow Jrow^T  (3x3),  b += Jrow r,   dp = -H^-1 b,   p += dp
```

Every pixel computes its residual and Jacobian row; a **block-level
shared-memory reduction** sums them into the shared 3×3 normal equations with
one global atomic per block (not per pixel — naive per-pixel atomics on the 11
accumulators are ~3000× slower from contention). The 3×3 system is solved on
the host and the pose updated; the demo animates the residual heatmap going
black as the warp locks on.

## Correctness — near-identical (not bit-exact), and accurate

The reduction is a cross-thread sum, so — unlike the per-feature LK demo — this
is **not** bit-identical: floating-point addition is non-associative and the
GPU's block-tree + atomic order differs from the CPU's sequential sum. Both
accumulate in **double precision**, so the per-term values match and only the
summation order differs.

| metric | value |
|---|---|
| CPU vs GPU recovered pose `max\|diff\|` | `~1e-11` (summation-order only) |
| ground-truth translation error | `0.0002 px` |
| ground-truth rotation error | `5e-7 rad` |
| photometric RMS | `14.1 → 0.04` |

The texture is smooth and band-limited so finite-difference gradients are
faithful and the alignment converges to the true SE(2) pose to a thousandth of
a pixel.

## Result (this machine)

| | scale | time | note |
|---|---|---|---|
| CPU serial | `512×512 × 25` GN iters | `~385 ms` | reference |
| **GPU** | one thread / pixel, block-reduced | **`~14.5 ms`** | **~27×** |

(The per-iteration host sync — upload pose, download the 3×3 system — caps the
speedup; the per-pixel residual+Jacobian+reduction is the parallel win.)

## Reproduce

```bash
cd build && cmake .. && make gpu_direct_vo -j$(nproc)
cd .. && ./bin/gpu_direct_vo
```

Prints the timing + CPU/GPU agreement + ground-truth accuracy table and writes
`gif/gpu_direct_vo.gif` (reference, current frame, and the photometric residual
heatmap shrinking to black as Gauss-Newton converges).

## Notes

- One demo = one `.cu`; reuses `include/cuda_check.cuh` and `include/cuda_video.h`.
- Forward-additive SE(2) Gauss-Newton; the 3×3 normal equations are reduced on
  the GPU and solved on the host (a 3×3 solve is not worth a kernel).
- `atomicAdd(double*)` is implemented via CAS so the demo builds on compute
  capabilities below 6.0 too.
- The current frame is generated by the exact SE(2) inverse warp of the
  reference, so the estimator recovers the ground-truth pose directly.
- `--fmad=false`; GIF served from gh-pages (not committed to the repo).
