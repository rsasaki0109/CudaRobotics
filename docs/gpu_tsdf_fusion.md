# GPU TSDF Volumetric Fusion

`gpu_tsdf_fusion` is the KinectFusion-style depth-integration step that the
repo's mapping section (occupancy grid, CSM / NDT submap SLAM, branch-and-bound
loop closure) did not yet cover. It fuses many depth frames from known poses
into a single dense Truncated Signed Distance Field, and demonstrates the
canonical mapping idiom: **one thread = one voxel**.

## Setup

- Volume: `96^3 = 884,736` voxels, axis span `5 m` per side
  (`VOXSZ ≈ 0.052 m`, truncation `MU = 0.20 m`).
- Depth source: `24` synthetic depth frames (`160 × 120`) generated by
  analytic sphere-tracing of a 3-sphere "snowman" on a ground plane, with the
  cameras orbiting the scene.
- For each voxel, every frame is integrated:
  - project the voxel centre into the camera (`pc = R (p - t)`),
  - read the measured depth at that pixel,
  - form the projective signed distance `sdf = depth_measured − pc.z`,
  - truncate to `[−MU, +MU]` (skip if `sdf < −MU`, i.e. occluded), and
  - fold into the running weighted average for that voxel.
- A single `__host__ __device__` `fuse_voxel(...)` is called by **both** a serial
  CPU triple loop and the batch CUDA kernel, so the two paths run the same
  arithmetic.

## Correctness — deterministic by construction

In sharp contrast to the iLQR demo (whose discrete line-search branches
introduced legitimate per-problem bimodality), TSDF fusion is a *deterministic
weighted average*. Each voxel processes the frames in the same fixed order on
the CPU and the GPU, with no data-dependent branches that could fork to a
different result. With FMA contraction disabled (`--fmad=false`), the CPU and
GPU volumes are **bit-identical**:

| metric | value |
|---|---|
| TSDF max&nbsp;\|diff\| (CPU vs GPU) | `0.0` |
| TSDF mean \|diff\| | `0.0` |
| observed voxels | `691,228` |

There is no honesty caveat here — the GPU is doing the *same arithmetic in
parallel*, and the win is pure throughput on the volume.

## Result (this machine)

| | voxels | time | note |
|---|---|---|---|
| CPU serial fuse | 884,736 × 24 frames | 134 ms | same `fuse_voxel` |
| **GPU fuse kernel** | 884,736 × 24 frames | **0.125 ms** | **~1075×** |

Per voxel-frame: CPU `6.3 ns`, GPU `0.006 ns`.

## Reproduce

```bash
cmake -S . -B build
cmake --build build --target gpu_tsdf_fusion -j$(nproc)
./bin/gpu_tsdf_fusion
```

Generated files:

- `tmp/gpu_tsdf_fusion.avi`
- `gif/gpu_tsdf_fusion.gif`

## Output

The GIF animates the zero-level-set surface refining as additional depth
frames are integrated and the view orbits. The info panel reports the frame
count, the fused-voxel and surface-band voxel counts, the CPU vs GPU fuse
time with speedup, and the CPU/GPU TSDF max-diff.
